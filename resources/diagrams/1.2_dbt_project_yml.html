Inside dbt_project.yml
the badge that makes the folder a dbt project — line by line
job_postings/dbt_project.yml
name: 'job_postings' version: '1.0.0' profile: 'job_postings' model-paths: ["models"] analysis-paths: ["analyses"] test-paths: ["tests"] seed-paths: ["seeds"] macro-paths: ["macros"] snapshot-paths: ["snapshots"] clean-targets: - "target" - "dbt_packages" models: job_postings: +materialized: table
name — the project's name; also namespaces its configs
profile — looked up BY NAME in ~/.dbt/profiles.yml. This one line is the cable between WHAT (this project) and WHERE (your warehouse)
*-paths — where dbt looks for each of the six folders from the anatomy. You'll almost never change these
clean-targets — what dbt clean deletes: build artifacts, never yours to edit
models: — materialization DEFAULTS, project-wide or per folder. One line here changes every model; a file's config() overrides it
lives IN the project, committed to git — it describes WHAT the pipeline is
