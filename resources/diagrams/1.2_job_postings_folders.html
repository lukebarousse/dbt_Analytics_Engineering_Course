Inside the dbt project
six folders, one job each — every one scaffolded by dbt init
job_postings/ the dbt project
dbt_project.yml  — the badge that makes this folder a dbt project
📁
models/
your SQL — one SELECT per file, versioned. The heart of every dbt project.
📁
seeds/
small lookup CSVs that live in the repo and load with one command.
📁
analyses/
scratch queries — compiled like models, never built into the warehouse.
📁
macros/
reusable SQL functions — you'll write your own.
📁
tests/
declared checks on your data — they fail loudly so bad data can't hide.
📁
snapshots/
row history — what changed, and when, as your data evolves.
dbt also generates target/, logs/, dbt_packages/ as it runs — build artifacts, not yours to edit
