Why the Direction Matters
written where the FK lives · FK → PK
the same test flipped · PK → FK
bridge_job_skills.skill_id
→ dim_skill.skill_id
every skill pair → the taxonomy
✓ PASS · 0 orphans
every skill somebody posted is in the taxonomy
✗ FAIL · 462 rows
462 seeded skills nobody has posted yet. That is fine.
bridge_job_skills.job_id
→ fct_job_postings.job_id
every skill pair → a real posting
✓ PASS · 0 orphans
every skill pair points at a posting that exists
✗ FAIL · 65,039 rows
13.2% of postings list no skills at all. Also fine.
fct_job_postings.company_name
→ dim_company.company_name
every posting → its company
✓ PASS · 0 orphans
every posting's company is in the dim
✓ PASS · 0 rows
passes, but only because dim_company is BUILT from fct
FK → PK asks: does every child have a parent?
Flipped, it asks: does every parent have a child? A different promise, and usually one nobody made.
